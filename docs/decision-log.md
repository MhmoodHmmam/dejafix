# Decision log

## R1: Project skeleton and Meko gateway (week 1)

- **Decision:** Django 5.2 LTS project. Meko is reached through our own async MCP gateway
  (`dejafix/meko/gateway.py`) built on the official `mcp` SDK, not through the model's MCP connector.
  - **Why:**
    - Meko identifies agents, conversations and datapacks by arguments, so code (not the model) must set them.
    - Calls are checked against the live schemas before sending, because Meko Cloud rejects unknown arguments.
    - Every call gets a timeout. Only read-only tools are retried, with backoff, so a timeout can't store the same memory twice.
    - Each call is recorded without its arguments, for our traces (A09).
- **Decision:** Build against the live tool schemas, saved by `manage.py meko_probe`, instead of the published docs.
  - **Why:** Meko Cloud publishes 57 tools. The docs miss several (`track_token_usage`, `selflearning_*`, `amp_*`).
  - Meko Cloud also requires `conversation_id` on calls whose schema marks it optional (for example, `datapack_list` answered with the in-band error `conversation_id_required`).
  - `conversation_create` requires a `datapack_id`, so the first datapack must be created in the portal.
- **Decision:** Secrets only from the environment (a stdlib `.env` loader, no new dependency).
  - `DEBUG` is off by default. `MekoConfig` hides the key from `repr`.
  - Plain HTTP is allowed only for a localhost Meko (A02, A04).
- **Rejected:**
  - The Anthropic MCP connector: the model would choose `agent_id`, and we'd lose per-call timeouts and records.
  - LangChain/Pydantic AI adapters: extra dependencies we don't need.
  - Self-hosting Meko: the README says Windows is not supported.
  - Django 6.x: 5.2 is the LTS release and supports Python 3.14.
- **Sources:**
  - [source] `mcp` 2.3.0 installed:
    - `mcp/client/client.py`: `Client`, `call_tool`, `list_tools(cursor=)`
    - `mcp/client/streamable_http.py`: `streamable_http_client(url, http_client=)`
    - `mcp_types/_types.py`: `CallToolResult.content`, `structured_content`, `is_error`; `ListToolsResult.next_cursor`
    - `mcp/server/mcpserver/server.py`: `MCPServer.tool`, used for the in-process test fake
  - [source] `httpx2` 2.16.2 installed: `HTTPStatusError(..., request=, response=)`, `AsyncClient`, `Timeout`
  - [read] Live Meko Cloud `tools/list` (saved to `docs/meko-tools.json`) and its in-band errors `conversation_id_required` and `datapack_id_required`
  - [read] github.com/yugabyte/meko `src/meko/docs/api.md`:
    - reply conventions: JSON as text, in-band `{"error","detail"}` with `isError: false`
    - Cloud rejects unknown arguments

## R2: Support agents, synthetic data and human review (week 2)

- **Decision:** A code-driven workflow (triage → retrieve → resolve → review), not a free agent.
  - Each agent is one Claude call with a Pydantic-typed output and **no tools**, so ticket text has nothing to act on.
  - Code runs the Meko calls in a fixed order, so "search before solving" can't be skipped.
  - The fixed order also keeps the benchmark repeatable.
- **Decision:** One Meko conversation per (ticket, agent).
  - Why: live schema says "Conversations are scoped per agent" and `conversation_add_message` needs the same `agent_id`.
  - All of a ticket's conversations share `run_id = dejafix:<ticket>`.
  - A fixed `session_id` and message `seed` make re-runs reconnect instead of duplicating.
- **Decision:** Retrieval uses `context_search` plus `knowledgebase_search`.
  - **Why:** live spike: a promoted memory disappears from memory search and comes back from `knowledgebase_search` (rerank 0.97 on a paraphrase). `context_search` did not return it, even with `force_source="knowledge_base"`.
- **Decision:** Only fixes promoted by the curator agent, in our exact text format, are trusted for reuse.
  - Corrections count only in their exact format.
  - **Why:**
    - Promotion is one-way: a test chunk from the spike could not be deleted.
    - Meko Cloud **auto-extracts memories from every conversation turn** under our agents' ids. A live run created 20 such memories, including unreviewed fixes. None contained the injection text.
- **Decision:** Memory is written only after a human decides.
  - Approval: the curator stores the fix and promotes it (collective memory).
  - Rejection: the reviewer's note is stored as a private learning, which resolvers see next time.
  - Approve/reject claim the row with a conditional `UPDATE` (no double promotion). The claim is released if Meko fails.
- **Decision:** Effort `low` for triage, reuse check and review; `medium` for solving. Server-side refusal fallback (`fallbacks="default"`) is on.
- **Live check (5 tickets + 1 approval, real Claude Opus 5.5 and Meko Cloud):**
  - T001 (new): 5,291 tokens, 13.1 s of model time.
  - Repeats T013, T025, T033 reused the approved fix:
    - 2,667 to 2,782 tokens each, about 49% fewer than T001.
    - 8.6 to 9.8 s of model time.
  - Cross-agent: T025 was handled by resolver-b. Cross-language: T033 is in Arabic.
  - Reuse scores were 0.994 to 1.0.
  - T013's reply adapted the approved fix to a bank holiday.
  - T017 (prompt injection) was escalated by the code rule; no memory was written.
- **Bug found by the live run:** the reviewer escalated a correct fix because it saw only policy passages, not the documentation the resolver used.
  - Fixed: the reviewer now gets the resolver's evidence.
  - Regression test: `test_reviewer_sees_the_documentation_the_resolver_relied_on`.
- **Rejected:**
  - Managed Agents / a tool-using agent: harder to enforce ordering and to benchmark, and a larger injection surface.
  - Trusting `context_search` alone: it misses promoted fixes.
  - Writing memory on every resolution: unreviewed fixes would be reused.

## R3: Self-learning loop and case files (week 3)

- **Decision:** Close knowledge gaps with Meko's own self-learning tools, with a human in the loop.
  - The loop: `find_gaps` → `draft_gap_articles` → a human publishes in the admin → `verify_gaps`.
  - `find_gaps` reads `selflearning_status`, then `selflearning_shortfalls(add_context)`, then `selflearning_query_log` for each search.
    - Shortfall rows don't name the agent, so the log entry is needed to keep only our resolvers' searches. The spike agent's searches are ignored.
    - The log entry also names the conversation, which links each gap to its ticket.
  - The librarian (`dejafix-librarian`, effort `low`, no tools) drafts only from human-approved resolutions plus documentation.
    - Without an approved fix, the gap becomes `needs_author` without calling Claude.
  - Publishing uploads a markdown document to the knowledge base.
    - **Why a document and not a memory:** `context_search` (which Meko grades) reads knowledge-base documents but not promoted memories.
    - The knowledge base is trusted context for every resolver, so only a human publishes.
  - `verify_gaps` replays the search with `selflearning_verify`.
    - The "before" values are frozen at publish time.
    - Replays are capped at 10 per run, the same as Meko's limit per minute.
- **Decision:** A case file (JSON) is stored as a Meko artifact (`artifact_put`) on every human decision. The shared memory links to it with a `Case file: <sha256>` line.
  - It holds no ticket text, customer or reviewer name.
  - It has no timestamps, so a retry produces the same bytes and Meko stores it once.
  - The case file is written before the memory, and a failure releases the review claim.
- **Live findings:**
  - Gaps were imported: card_closed refund (T017), bank holiday (T013) and weekend (T001).
    - T017 was escalated, so it has no approved fix and became `needs_author`.
    - Two drafts were made for 4,009 tokens. Before publishing, I checked them line by line against `payouts.md` and the approved T001 fix: nothing was invented.
  - Replays:
    - Bank holiday: mid 0.68 → high 0.78.
    - Weekend: mid 0.69 → high 0.87.
    - Meko's Self-learning tab marks both searches `verified`.
  - **Attribution caveat:** the replay grades every source. Its top 5 hits were past *conversations*, including our own trace turns, which hold the search text.
    - Part of the jump comes from history that piled up after the first search, not from the article.
    - So `verify_gaps` now records the replay's top source (`source_after`) and the article's own knowledge-base rank (`kb_rank_after`).
    - Live, both articles rank #1 in the knowledge base for their search, above the original payouts doc.
    - A KB-only `context_search` graded the weekend query `high` and the holiday query `mid`.
  - **Bug found by the live run:** `conversation_create` returns 32 hex digits, but the search log writes the same id as a UUID with hyphens, so no gap was linked to its ticket.
    - Fixed by normalizing both sides in the query (`Lower(Replace(...))`).
    - Regression test: `test_links_the_ticket_when_the_log_writes_the_conversation_id_as_a_uuid`.
- **Rejected:**
  - `memory_add` to close gaps: `context_search` does not grade promoted memories.
  - Publishing drafts without a human: it would poison trusted context.
  - Trusting Meko's replay band alone: it counts our own traces (see the caveat above).
- **Sources:**
  - [read] Live schemas: `selflearning_status`, `_shortfalls`, `_query_log`, `_verify` (owner role, 10 replays a minute, counts against search quota), `artifact_put` / `artifact_get` (idempotent, < 1 MB inline), `knowledgebase_upload_document` ("passages come back from knowledgebase_search and context_search").
  - [read] Live replies: status (quality 25%, `add_context` with 9 searches), shortfalls, a full query-log entry (`agent_id`, `conversation_id`, `source_outcomes`), and a verify reply (`before` / `after` / `outcome` / `top_results[].s`).
  - [source] Django 5.2.19 installed:
    - `CheckConstraint(condition=...)` in `db/models/constraints.py`
    - `Replace` and `Lower` in `db/models/functions/text.py`
    - `ModelAdmin.get_readonly_fields` and action `allowed_permissions` in `contrib/admin/options.py`
  - [knowledge] OWASP Top 10:2025:
    - A01: publish and dismiss are staff actions with change permission.
    - A05: weak-search text is escaped in `<weak_search>`.
    - A06: human gate before the knowledge base; conditional-update claims for publish and verify.

## R4: Benchmark with and without shared memory (week 4)

- **Decision:** Two arms over all 36 tickets, in ticket order, with the same agents, prompts, effort and documentation.
  - Each arm runs in its own new datapack, created with `datapack_create` and seeded with the same 9 docs.
  - The only difference is memory. The docs-only arm runs the same Meko searches but keeps only documentation passages.
  - Each run trusts only its own curator and reviewer identities. Ticket refs are prefixed with the run name, so traces never collide.
- **Decision:** Deterministic grading against ground-truth keywords per issue (`data/tickets.json`), not an LLM judge.
  - A fix is correct only if it mentions every keyword and was not escalated.
  - The two injection tickets are flagged in the ground truth and must be escalated with nothing stored.
  - The rules were fixed before the run and not changed after seeing results, even where they are strict (T003: "use a live key" without the `lp_live_` prefix counts as wrong).
- **Decision:** A simulated reviewer in the Meko arm decides each new fix right away.
  - It approves complete fixes. It rejects incomplete ones with a note naming the missing keywords.
  - Its notes come from the ground truth, so it is kinder than a busy human. The report says so.
- **Results** (one run per arm, `claude-opus-5-5`; full table in `docs/benchmark.md`):
  - Correct: docs-only 25/36, Meko 30/36. First occurrences 8/12 in both; repeats 17/24 vs 22/24.
  - Tokens on repeats: 5,348 vs 3,537 on average (-34%). Total: 192,558 vs 148,998 tokens ($1.43 vs $1.11 at list price).
  - Human touches: 36/36 vs 19/36 (17 repeats reused an approved fix).
  - False reuse 0. Both injection tickets escalated with nothing stored, in both arms.
  - Learning from corrections: T002, T003 and T010 were rejected with notes, and their repeats T014, T015 and T023 were correct in the Meko arm but wrong in the docs-only arm.
  - The reuse check works as a gate: T036 was offered T012's fix at score 1.0, judged a different cause, and solved correctly from the docs.
- **Calibration:** every threshold from 0.50 to 0.90 gave precision 1.00 and recall 1.00. No other issue's fix was ever offered, so the data cannot test how low the threshold can safely go. `REUSE_MIN_RERANK_SCORE` stays at 0.80.
  - The first report said "Recommended: 0.5". That falsely precise value was replaced by the tied range, with an explicit caveat.
- **Bugs found while building the benchmark:**
  - **Security:** an injection ticket matching an approved fix took the reuse path, which skips review, so the "instructions in the ticket → escalate" rule never ran and the ticket closed with a model-written reply. Fixed: injection tickets never take the reuse path. Regression test: `test_injection_ticket_is_escalated_even_when_an_approved_fix_matches`.
  - **Security:** human corrections were trusted by their text format alone, from any agent (memory search spans every agent). Fixed: only the reviewer agent's corrections count; live `context_search` memory hits carry `agent_id`. Regression test: `test_correction_written_by_an_untrusted_agent_is_ignored`.
- **Limits:** one run per arm (no repeated runs, so no confidence intervals); 36 synthetic tickets; a lenient simulated reviewer.
- **Rejected:**
  - Running both arms in the demo datapack: it already holds a promoted fix and two articles, and `knowledgebase_search` keeps only the top 8 hits.
  - An LLM judge: costlier, and harder to repeat than keyword grading.
